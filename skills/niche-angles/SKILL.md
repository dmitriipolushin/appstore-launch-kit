# niche-angles

Задача — **найти углы**, а не оценить нишу целиком. Угол = конкретное позиционирование: для кого + какое обещание («AI-разговорный английский для Тайваня и Вьетнама», «стих дня на экране блокировки»), а не тема («языки»). Деньги в широкой нише почти всегда сосредоточены в 1–3 таких углах — их и ищем по тому, что продают новички.

Источники: AppStoreSpy (оценки выручки/загрузок — модель, а не факт), iTunes Lookup (скриншоты, описания), подсказки App Store, Apple Ads Platform API (search-term-popularity). Весь текст отчёта — по-русски.

## Первоначальная настройка (один раз)

Ключи — в `~/.config/aso-tools/api_keys.env` (шаблон — `config/api_keys.env.example` в репозитории), скрипты читают их сами (`scripts/env_setup.py`). Ключи никогда не печатай.

- `APPSTORESPY_API_KEY` — обязателен: подниши, выручка, subtitle, гео, рекламные сети.
- `ASA_CLIENT_ID`, `ASA_KEY_ID` (+ `ASA_ORG_ID`) и PEM-ключ в `~/.config/aso-tools/keys/` — для шага 5 (popularity в Apple Ads). Без них шаг 5 пропусти и скажи пользователю, что спрос в поиске не измерен.
- OCR скриншотов — только macOS: `scripts/ocr` собирается из `scripts/ocr.swift` при первом запуске `apps.py` (нужен `swiftc` из Xcode Command Line Tools). На другой ОС `apps.py` пропускает OCR с предупреждением — оффер и джобу пиши по subtitle и описаниям.

Если чего-то не хватает — не угадывай значения, а скажи пользователю, какой переменной нет.

Все скрипты — в `~/.claude/skills/niche-angles/scripts/`: свои `apps.py`, `asa.py`, `report.py`, `common.py` и симлинки на общий код кита (`niche_analyzer.py`, `keyword_suggest.py`, `appstorespy.py`, `asa/platform_api.py`). Ниже `S=~/.claude/skills/niche-angles/scripts`. Читаешь скилл из клона без установки — `S=<репозиторий>/skills/niche-angles/scripts`. Интерпретатор — тот, что `./install.sh --check` отметил ✓.

Подниши считает тот же `niche_analyzer.py`, что и скилл [`niche-analysis`](../niche-analysis/SKILL.md): критерии и пороги — оттуда.

## Структура проекта

```
<project>/                      # напр. ./<niche>-angles/
  config.json                   # всё, что пишешь руками (формат ниже)
  sub/<sub>/candidates.csv      # подниши: niche_analyzer collect → чистка include → score
  sub/<sub>/metrics.json
  hints_<cc>_<тема>.json        # keyword_suggest (подсказки App Store)
  cache_apps.json, cache_ocr.json, shots/   # apps.py
  asa_raw.json, popularity.json             # asa.py
  report.html                               # report.py
```

`config.json` (полный рабочий пример — `examples/sports_video.config.json`):
```json
{
 "niche": "Видео-хайлайты для падела и тенниса",
 "participant": "Участник: …",            // необязательно
 "title": "Углы: падел-хайлайты",          // <title> страницы
 "as_of": "2026-10-28",                   // дата сбора; «новые» = релиз не раньше as_of − 2 года
 "countries": ["US","GB","CA","AU","DE","FR","ES","IT","BR","MX","JP","KR","TW"],
 "angles": [{
   "id": "club-cam",                      // якорь в отчёте
   "sub": "club_cam",                     // папка sub/<sub>
   "title": "Клубная камера → автохайлайты для игроков",
   "apps": ["412223222", "1573754839"],   // примеры-конкуренты; null — новички подниши с выручкой ≥ $5k; [] — показать лидеров
   "comp_note": "…",                      // необязательно: заголовок над карточками конкурентов
   "score_note": "…",                     // необязательно: оговорка к скору (напр. B2B-выручка не видна в App Store)
   "essence": "суть угла, 4–6 предложений с цифрами",
   "offer": "главный оффер", "job": "Когда я…, я хочу…, чтобы…", "hooks": ["…"],
   "keywords": [{"kw": "padel", "country": "es"}],
   "asa": {"roots": [["ES","padel"]], "terms": [["es","padel","g"],["es","playtomic","b"]], "verdict": "вывод по поиску"}
 }],
 "rejected": [{"title": "…", "reason": "…"}]
}
```
Приложение из `apps` должно быть в каком-нибудь `sub/*/candidates.csv` (если нужно только показать, но не считать — добавь строку с `include=0`).

## Шаги

### 1. Карта ниши и новички
1. `python3 $S/niche_analyzer.py collect --project <P>/sub/_wide --name … --seed …` — широкий сбор по 3–6 формулировкам и 2–4 seed-приложениям лидеров (seed находит тех, у кого ключевого слова нет в названии). Seed ID ищи через iTunes Search: `curl "https://itunes.apple.com/search?term=…&entity=software&country=us&limit=10"`.
2. Выпиши **новых** зарабатывающих (релиз ≥ as_of − 2 года, выручка ≥ $5k) с subtitle — по ним видно, какие обещания сейчас продаются. Это сырьё для углов.
3. Дополнительно ищи в выдаче App Store (iTunes Search) узкие запросы угла — там находятся свежие приложения, которых AppStoreSpy ещё не поймал по названию; выручку доберёшь `appstorespy.get_app(id, fields=[…])`.

### 2. Углы → подниши
1. Сформулируй 5–8 кандидатов-углов (для кого + обещание). Для широкой ниши — обязательно по рынкам/языкам и по аудиториям, не только по функциям.
2. Под каждый — своя подниша `sub/<sub>`: `collect` с узкими `--name`/`--seed` или ручная сборка `candidates.csv` из пула (колонки: include,id,name,developer_name,category,category_type,release_date,revenue_month,downloads_month,source; meta.json скопируй из любой подниши).
3. **Чистка строго**: в поднише только приложения, чьё *главное* обещание — этот угол (смотри subtitle, первую строку описания, скриншоты). Игры, гиганты-комбайны, соседние ниши — `include=0`. Сомневаешься — спроси пользователя.
4. **Одно приложение — один угол.** Если приложение подходит к двум, оставь его там, где его главное обещание (пример: Scout — сканер продуктов с поиском ресторанов → угол «сканер», не «еда вне дома»). `report.py --check` ловит пересечения.
5. `python3 $S/niche_analyzer.py score --project <P>/sub/<sub>` (пороги дефолтные, не меняй).
6. Если книга-саммари, social intelligence и т.п. смешались в одном угле — разведи на разные подниши и пересчитай: смешение искажает «долю новых».

### 3. Отбор и ранжирование
- Углы **не обязаны** проходить все 5 критериев. Ранжирование — по скору «шансы соло-разработчика» (`common.score`): малые новички $5–30k — 25, доля новых — 25, доля лидера — 15, RPD — 15, выручка — 10, число зарабатывающих — 10; опорное значение = половина веса, вдвое лучше = полный вес. 70+ сильный, 50–69 средний, <50 слабый.
- Оставь 3 лучших угла (больше — если пользователь просит смежные ниши), остальные — в `rejected` с причиной и цифрами.
- Подниша из 1–2 зарабатывающих приложений даёт ложные 100% «доли новых» — оговори это в essence.
- B2B/hardware-модели (клубные камеры, сервисы для бизнеса) в App Store почти не видны → `score_note`.

### 4. Конкуренты, скриншоты, оффер и джоба
1. Заполни `apps` (или оставь `null`), затем `python3 $S/apps.py --project <P> --digest`.
   Печатает по углам: название, subtitle, тексты со скриншотов (OCR), начало описания.
   Для приложений без выручки (новые конкуренты того же формата) — `--ids 1,2,3 --digest`: их офферы тоже полезны, но в карточки они не попадают.
2. По digest напиши в config для каждого угла:
   - `offer` — главное обещание, общее для новичков угла, одной фразой;
   - `job` — «Когда я …, я хочу …, чтобы …» (ситуация → мотивация → результат);
   - `hooks` — 4–6 повторяющихся фраз/фич со скриншотов, дословные цитаты в «».
   OCR плохо читает японский/стилизованный текст — тогда опирайся на описание и скажи об этом.
3. В отчёт попадают только приложения с выручкой или загрузками > 0 (фильтр в `common.angle_apps`).

### 5. Ключи и поисковый спрос (Apple Ads)
1. Подсказки App Store: `python3 $S/keyword_suggest.py --seeds "a,b,c" --country us --rate 0.5 --out <P>/hints_us_<тема>.json` (≤10 сидов, медленно — запускай в фоне). Из результатов выбери 6–12 общих EXACT-ключей на угол → `keywords` (страна = сторфронт: для Японии ключи на японском и т.д.).
2. `asa.roots` — корневые подстроки угла по странам (на языке страны). `python3 $S/asa.py --project <P> discover` печатает все головные запросы с ними — в выдаче много мусора (Microsoft, Skyscanner…), отбери руками релевантные в `asa.terms` с типом `g` (общий) или `b` (бренд конкурента).
3. `python3 $S/asa.py --project <P> measure` — popularity ключей и терминов по `countries` за последний месяц + тренд 12 мес.
4. Напиши `asa.verdict`: есть ли поисковый спрос, растёт/падает, где по странам, бренды-лидеры, и что это значит для канала (ASA основной / вторичный / только перехват бренда).
   Правила чтения: покрытие только «голова» (порог ≈ 45–50) — «—» значит малый объём, не ноль; высокая popularity общих запросов = дорогой клик и размытый интент; лучший ASA-ключ — точный интент 50–65 с растущим трендом; для неанглоязычных рынков ищи спрос на родном языке (например, 英会話, 영어회화).
   `keyword_suggestions` (подсказки с popularity) работает только для приложений из своей ASA-организации — для чужих ниш почти пустой.

### 6. Отчёт
`python3 $S/report.py --project <P>` → `<P>/report.html`. Сначала `--check`. Открой отчёт (headless Chrome скриншот) и проверь вёрстку. Картинки грузятся с серверов Apple — HTML можно пересылать одним файлом, получателю нужен интернет.

## Правила

- Работай сам и последовательно: десятки параллельных субагентов на этой задаче работают дольше, чем один проход, и дублируют запросы к API.
- AppStoreSpy иногда обновляет месяц оценок посреди работы (цифры падают в 3–5 раз) — собирай всё за один день, при скачке оговори в отчёте.
- Не выдумывай popularity и выручку. Нет данных — так и пиши.
- Выводы — с цифрами; пограничные значения называй пограничными.
- Ничего не создавай в Apple Ads (кампании, адгруппы) — скилл только читает.
