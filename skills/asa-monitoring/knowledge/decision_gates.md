# Decision Gates

**Читать перед шагом 4. Каждая рекомендация должна пройти соответствующий gate.**

---

## GATE 1 — Поднять бюджет?

Две проверки, строго в этом порядке. Расход ниже 90% лимита **сам по себе не означает**,
что бюджет поднимать не надо.

**Проверка 1 — не занижен ли бюджет в абсолюте.** Считай, сколько установок бюджет вообще
разрешает купить: `daily_budget ÷ CPI`.

Слишком низкий дневной лимит — это сообщение алгоритму Apple «нам нужно всего несколько
установок в день», и открутка пессимизируется. Кампания не откручивает даже свой маленький
лимит именно потому, что лимит маленький.

> Пример: CPI $2 при бюджете $6/день = «мы готовы купить 3 установки». Поднятие лимита
> до $12 может дать фактический расход $10 — не потому что разрешили больше, а потому что
> перестали ограничивать алгоритм.

- `daily_budget ÷ CPI` меньше ~5 установок → **raise budget обоснован даже при расходе ниже 90%**
- Поднимать примерно вдвое и смотреть **фактический** расход через день, а не ожидаемый
- Если после поднятия расход не вырос — вот теперь ограничение в аукционе, идти в GATE 2

**Проверка 2 — упирается ли расход в лимит.** `spend_7d ÷ 7 ÷ daily_budget × 100%`

- ≥ 90% → кампания budget-limited → **raise budget обоснован**
- < 90% **при бюджете, который уже даёт ≥ 5 установок** → кампания auction-limited →
  бюджет не поможет, нужен raise bid (GATE 2)

Правило «не поднимать бюджет при расходе < 90%» действует только после Проверки 1.

## GATE 2 — Поднять ставку?

Выполнить **все три проверки** по порядку:

**2a. IS проверен?**
- Если IS-отчёт ещё не запущен → запусти его сейчас (шаг 3.4), не предлагай bid raise без IS.
- Исключение: кампании с 0 impressions — IS не нужен, сразу +$0.20.

**2b. IS < 90%?**
- IS < 90% → raise bid обоснован
- IS ≥ 90% → ключ у потолка, raise bid не поможет → **предложи новые ключи вместо raise**

**2c. CPTrial приемлемый?**
- CPTrial < $20 → raise bid обоснован
- CPTrial > $20 при > 15 installs → сегмент дорогой, raise bid усилит убыток → **сначала пауза или оптимизация страницы**
- < 5 installs → мало данных, CPTrial не считать, raise bid допустим

## GATE 3 — Паузировать?

Пауза обязательна при любом из условий:

| Условие | Действие |
|---|---|
| 0 impressions при bid ≥ clearing price **3+ дней** | Pause — нет объёма в аукционе |
| > 15 installs + 0 trials | Pause — сегмент не монетизируется |
| trial rate < 3% при > 15 installs | Pause — аудитория не конвертится в платящих |
| 0 installs при taps > 15 | Pause keyword — трафик нерелевантен |

**Диапазоны ожидания — два пути:**

**Если триалы есть (≥ 1):** считай CPTrial = spend / trials. Пауза если CPTrial > max_cptrial.
max_cptrial = LTV × TTP — читать из `unit-economics/asa_pause_strategy.md` каждую сессию, не хардкодить.
CPI сам по себе не повод для паузы — высокий CPI при хорошем trial rate может быть окупаемым.

**Если 0 триалов:** порог зависит от CPI (чем дороже установка, тем быстрее пауза):

| CPI | Пауза при 0 триалах |
|---|---|
| ≤ $1.50 | После **15 installs** |
| $1.50–$2.50 | После **10 installs** |
| $2.50–$3.50 | После **5 installs** |
| > $3.50 | После **3 installs** |

> Источник: `unit-economics/asa_pause_strategy.md`

## Пороги для оценки

**IPM** = installs / impressions × 1000

| IPM | Оценка |
|---|---|
| > 15 | Хорошо |
| 8–15 | Нормально |
| < 3 при 30+ impr | Проблема воронки |
| 0, taps > 0 | CR проблема (страница) |
| 0, taps = 0 | CTR проблема (bid / объявление) |

**CPTrial**

| CPTrial | Оценка |
|---|---|
| < $5 | Хорошо — масштабировать |
| $5–10 | Приемлемо — наблюдать |
| $10–20 | Дорого — оптимизировать |
| > $20 | Пауза |

**Trial rate**

| TR% | Оценка |
|---|---|
| > 15% | Сегмент монетизируется хорошо |
| 8–15% | Нормально |
| 3–8% | Слабо |
| < 3% при > 15 inst | Пауза |

**TTR**

| TTR | Оценка |
|---|---|
| > 3% | Хорошо |
| 1–3% | Приемлемо |
| < 1% при 100+ impr | Объявление нерелевантно |
