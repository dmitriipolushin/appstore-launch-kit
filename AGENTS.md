**Читаешь это как AI-агент? Этот файл — твоя точка входа. Прочитай его целиком до первого действия.**

## Что это за репозиторий

Набор инструментов для заполнения данных приложения в App Store: метаданные (title / subtitle / keyword field / description), скриншоты и прохождение модерации.

Это **не библиотека для импорта и не приложение для запуска.** Это набор инструкций, скриптов и справочных данных. Ты — исполнитель, репозиторий — твоя методология.

Здесь нет исходников чьего-либо приложения. Ты применяешь это к приложению пользователя, которое находится где-то ещё.

## Полный маршрут запуска приложения

Если пользователь идёт от начала до публикации — порядок такой. Каждый шаг зависит от предыдущего.

```
1. ASO-исследование          → skills/aso-collection/SKILL.md, шаги 1–6
   (конкуренты, ключи, Search Popularity, позиции, gap-анализ)
                ↓
2. Метаданные                → skills/aso-collection/SKILL.md, шаги 7–8
   (title, subtitle, keyword field, чеклист локалей)
                ↓
3. Description               → skills/aso-collection/SKILL.md, шаг 9
   (нужны финальные ключи из шага 2 + ссылки на ToU/PP от пользователя)
                ↓
4. Скриншоты                 → skills/app-store-screenshots/SKILL.md
   (нужны целевые ключи из шага 2 — они идут в текст на скриншотах)
                ↓
5. Заливка в ASC             → skills/asc-metadata/SKILL.md
   (или вручную, если у пользователя нет API-ключей)
                ↓
6. Подготовка к модерации    → docs/app-store-review-guide.md
   (Notes, пейвол, permissions, сводный чеклист перед отправкой)
```

**Почему именно такой порядок:** ключевые слова нужны и для description, и для текста на скриншотах (с июня 2025 Apple индексирует подписи на скриншотах). Если сделать скриншоты до keyword research — придётся переделывать.

## Правила, которые нельзя нарушать

Это не рекомендации. Нарушение каждого из них означает либо реджект, либо бесполезную работу.

### 1. Спроси про функции приложения до того, как писать ключи

**Не добавляй в метаданные ключи, описывающие функции, которых в приложении нет.** Если ключ описывает конкретную фичу (клонирование голоса, офлайн-режим, экспорт, сканирование) — сначала уточни у пользователя, есть ли она. Ключ на несуществующую фичу = реджект по Guideline 2.3.

### 2. Спроси про монетизацию

Полностью бесплатно / freemium (что именно бесплатно, что платно) / платно. Это влияет на:
- допустимость слова «бесплатно» в видимых полях (Guideline 2.3.2)
- обязательный абзац в description о том, что бесплатно и что по подписке

### 3. Не публикуй и не заливай ничего без подтверждения пользователя

Метаданные, description, скриншоты, PATCH-запросы в App Store Connect — **всё показываешь пользователю и ждёшь явного «да».** Заливка метаданных меняет живую страницу приложения в сторе.

### 4. Не выдумывай данные

- Search Popularity берётся **только** из Apple Search Ads (`skills/aso-collection/scripts/asa/keyword_popularity.py`). Нельзя оценить объём запроса на глаз.
- Apple Search Hints дают порядок подсказок, но **не объём** — термин с Hints 10000 может иметь ASA Popularity 5. Всегда верифицируй.
- Subtitle конкурентов **не возвращается** iTunes Lookup API. Только через AppStoreSpy (`/v1/ios/apps/{id}` → поле `short`).
- Если нужного API-ключа нет — скажи об этом прямо и предложи то, что можно сделать без него. Не заполняй пробелы догадками.

### 5. Скриншоты — только реальные экраны приложения

Оформление, фон, подписи, рамки устройства — можно. Придуманные интерфейсы, которых нет в билде, — нельзя, это гарантированный реджект. Если у пользователя нет реальных скриншотов — запроси их, не рисуй.

### 6. Subtitle — фраза, а не список через запятую

Плохо: `трек, кавер, лирика`. Хорошо: глагол + объект + дифференциатор, законченная читаемая фраза, которая сама является поисковым запросом.

### 7. Прочитай каждый заголовок вслух

После формулировки title и subtitle для каждой локали — прочитай. Если режет ухо, переформулируй. Keyword stuffing индексируется, но убивает конверсию, а конверсия — сама фактор ранжирования.

### Приоритет источников при конфликте

Если два файла противоречат друг другу, верь в этом порядке:

1. `skills/aso-collection/knowledge/` — самые свежие данные (2025–2026), с источниками и датами
2. `docs/app-store-review-guide.md` — практика прохождения модерации
3. `skills/app-store-optimization/` — более старый набор (ноябрь 2025), лимиты полей корректны, но требования к скриншотам и размерам могли устареть

Требования Apple меняются. Если что-то похоже на устаревшее (размеры экранов, лимиты, названия полей) — проверь в актуальной документации Apple, а не полагайся на репозиторий.

## Ключи и внешние сервисы

`skills/aso-collection/` — единственная часть, которой нужны внешние ключи. Всё остальное работает без них.

| Нужен для | Ключ | Где взять |
|---|---|---|
| Профили и subtitle конкурентов, поиск приложений | `APPSTORESPY_API_KEY` | appstorespy.com |
| Search Popularity ключевых слов (0–100) | `APPLE_SA_COOKIE` + `APPLE_SA_XSRF` | cookie из DevTools на app-ads.apple.com, живёт ~24 часа. Процедура — в `skills/aso-collection/SKILL.md`, шаг 4В |
| Заливка метаданных в App Store Connect | `.p8` ключ + KEY_ID + ISSUER_ID | App Store Connect → Users and Access → Integrations |

Установка: скопируй `config/api_keys.env.example` в `~/.config/aso-tools/api_keys.env` и заполни.

**Что работает вообще без ключей:** iTunes Lookup API (профили, рейтинги, description конкурентов), Apple Search Hints (`keyword_suggest.py`), позиции в поиске (`search_positions.py`), отзывы (`fetch_reviews.py`), все скрипты в `app-store-optimization/`, вся методология и knowledge-база.

Если ключей нет — работай по методологии на данных без ключей и **явно скажи пользователю, какая часть анализа осталась непокрытой.** Не выдавай неполный анализ за полный.

## Пути внутри скиллов

Файлы `SKILL.md` написаны для случая, когда скиллы установлены в `~/.claude/skills/`, и содержат абсолютные пути вида:

```
~/.claude/skills/aso-collection/scripts/keyword_suggest.py
```

**Если скиллы не установлены, а ты читаешь их из клона репозитория** — подставляй вместо `~/.claude/skills/` путь `<репозиторий>/skills/`. Например:

```bash
python3 ./skills/aso-collection/scripts/collect_profiles.py --project ./aso-collection --app-ids 284882215
```

Установить как обычные скиллы (тогда пути в SKILL.md станут верными):

```bash
for s in aso-collection app-store-optimization app-store-screenshots asc-metadata; do
  ln -sfn "$PWD/skills/$s" ~/.claude/skills/$s
done
```

Зависимости Python-скриптов `aso-collection`:

```bash
pip install requests python-dotenv PyJWT cryptography
```

## Работа с примером генератора скриншотов

`examples/screenshots-generator/` — реально использованный генератор (приложение-сканер состава продуктов, 4 локали, экспорт в PNG под размеры Apple).

**Используй его как референс кода, а не пиши генератор с нуля.** Что оттуда брать:

| Что нужно | Где смотреть |
|---|---|
| Полный слайд-сет с локалями | `src/app/general/[locale]/page.tsx` (~920 строк — самый развитый) |
| Вариант под конкретную нишу | `src/app/gluten/en/page.tsx`, `src/app/halal/de/page.tsx` |
| Экспортные размеры и логика выгрузки | там же, константы `SIZES` и обработчик экспорта |
| Макет iPhone | `public/mockup.png` |
| Как раскладывать реальные скриншоты | `public/screenshots/` |

Запуск: `npm install && npm run dev` → localhost:3000.

Методология (что писать на слайдах, в каком порядке, какие размеры экспортировать) — в `skills/app-store-screenshots/SKILL.md`. Пример показывает, **как** это реализовано в коде; скилл говорит, **что** должно получиться.

## Итоговый чеклист для тебя как агента

Прежде чем отдать результат пользователю:

- [ ] Уточнил функции приложения — в ключах нет несуществующих фич
- [ ] Уточнил модель монетизации
- [ ] Search Popularity взята из ASA, а не оценена на глаз (или явно сказано, что данных нет)
- [ ] Нет дублирования слов между title / subtitle / keyword field внутри локали
- [ ] Keyword field заполнен минимум на 85% лимита
- [ ] Subtitle — читаемая фраза, а не список
- [ ] Заголовки прочитаны вслух
- [ ] Для freemium в description есть явное «что бесплатно / что платно»
- [ ] В description есть ссылки на Terms of Use и Privacy Policy
- [ ] Скриншоты собраны из реальных экранов приложения
- [ ] Ничего не залито в App Store Connect без подтверждения пользователя
- [ ] Явно перечислено, что осталось непокрытым и почему
