# Пример: генератор скриншотов для App Store

Рабочий генератор, использованный для реального приложения (сканер состава продуктов). Next.js + `html-to-image` + `jszip`: слайды рендерятся в браузере в полном разрешении и выгружаются в PNG под размеры Apple, весь набор — одним zip.

**Это референс кода, а не заготовка.** Методология — что писать на слайдах, в каком порядке, какие размеры экспортировать — в [`../../skills/app-store-screenshots/SKILL.md`](../../skills/app-store-screenshots/SKILL.md). Здесь показано, как это выглядит в коде.

---

## Запуск

```bash
npm install && npm run dev
```

Открыть http://localhost:3000 — там хаб со ссылками на все наборы слайдов.

## Что здесь показано

### 1. Несколько наборов слайдов = Custom Product Pages

| Роут | Что это |
|---|---|
| `/general/[locale]` | Основной набор для страницы приложения. 7 слайдов, 5 локалей (en, de, fr, es, ru) |
| `/gluten/en`, `/gluten/de` | Custom Product Page под аудиторию с непереносимостью глютена |
| `/halal/de` | Custom Product Page под халяльную аудиторию |

Одно приложение, разные наборы скриншотов под разные сегменты. С июля 2025 CPP показываются в органических результатах поиска — то есть отдельные наборы работают и без платного трафика.

### 2. Локализация без дублирования кода

Пути к изображениям и словарь текстов разведены: слайд-компоненты одни и те же, меняется только `locale` в URL. Смотреть:

- `LOCALES` и `CONTENT` в `src/app/general/[locale]/page.tsx` (~строка 729) — словарь копирайта по локалям
- Пути к скриншотам собираются от локали, сами компоненты слайдов не знают о языке

Локализованные скриншоты помогают ранжироваться в региональных сторах даже если само приложение на английском.

### 3. Экспорт в размеры Apple

```
Дизайн:  1320 × 2868  (6.9", самый большой iPhone)
Экспорт: 1284 × 2778  (6.7")
iPad:    2048 × 2732  (13")
```

Принцип: **верстать в самом большом размере и масштабировать вниз** при экспорте. Обратное — растягивание — даёт мыло.

Ключевые места в коде (`src/app/general/[locale]/page.tsx`):

| Что | Где |
|---|---|
| Размеры холста и экспорта | строки 8–23, константы `W_PHONE` / `PHONE_SIZES` / `IPAD_SIZES` |
| Промеренные координаты экрана в макете iPhone | строки 26+, `MK_W` / `SC_L` / `SC_T` — не менять, они под `public/mockup.png` |
| Компонент `Phone` | ~строка 235 — макет + скриншот в вырезе экрана |
| Слайды | `Slide1`–`Slide7`, ~строки 251–688 — по одному компоненту на слайд |
| Превью в сетке | `Preview`, ~строка 688 — CSS-scale от полного разрешения |
| Логика экспорта и zip | `renderToBlobs` в `Page`, ~строка 750 |

### 4. Двойной вызов `toPng` — обязательный трюк

Первый вызов подгружает шрифты и картинки, второй даёт чистый результат. Без этого экспорт выходит пустым или без шрифтов. Смотреть в `renderToBlobs`.

Аналогично: элемент для экспорта висит за экраном (`left: -9999px`) и перед захватом временно возвращается на `left: 0`.

## Что менять под своё приложение

1. `public/screenshots/` — свои реальные скриншоты приложения (только реальные экраны, придуманные интерфейсы = реджект)
2. `public/app-icon.jpg` — своя иконка
3. `CONTENT` и `LOCALES` — свой копирайт и свои локали
4. Компоненты `Slide1`–`Slide7` — свои слайды, цвета, композиция
5. `PHONE_SIZES` — свои экспортные размеры, если нужны другие

`public/mockup.png` и константы `MK_*` / `SC_*` оставить как есть — координаты промерены под этот макет.

## Оговорки

- Слайды в этом примере довёрстаны под конкретный брендинг и конкретное приложение — это не универсальный шаблон, а пример реализации
- Экспортные размеры зашиты те, что были нужны на момент работы. Актуальные требования Apple проверяйте в App Store Connect
- `src/app/v2/[locale]` и `src/app/en` — редиректы на `/general`, остались от предыдущей итерации
